Cardiovascular device recalls rose from 281 to 482 in one year. Why?

The FDA recalls a device already in use when it may hurt people (a Class I recall means a reasonable probability of serious adverse health consequences or death; FDA definition). Counting recalls can mislead: 54 of those recall entries were really one problem at one company. This agent explains what is behind the numbers and shows where every figure comes from, so you can check it yourself. If it cannot back a number up, it says nothing.

How a question becomes a verified answer

Coral boxes are model calls, grey boxes are plain code, green is a verified answer. The model never checks itself: the evaluator is code.

STEP 1
Question
A "why did this change?" question about FDA device recalls.
STEP 2
Scope check
Code refuses off-topic questions and years the data does not hold, before any model call.
STEP 3
Drafter
An AI model (NVIDIA Nemotron) writes the answer, and every number must point to the data it came from.
STEP 4
Evaluator
Plain code, not the AI, re-checks every number against the data and rejects anything it cannot confirm.
STEP 5
Verified answer
Each number links to its proof. Report, run log and receipts are saved.
Rejected? The evaluator names the reason (no citation, wrong scope, value mismatch, an unclaimed number) and sends it back for a redraft on a larger Nemotron model. Missing detail triggers a research step that fetches it from Zetaris.
Zetaris serves the data: guarded, read-only SQL, one SELECT per call, openfda tables only. H-MEM recalls earlier verified claims as hints (never evidence) and stores new ones with their SQL.
